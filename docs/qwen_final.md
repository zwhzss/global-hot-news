全球热点资讯聚合系统
架构设计文档（最终版）
本文档在原始需求（需求.md）的基础上，综合三版大模型架构设计（qwen、deepseek、doubao）的各自优点，给出面向个人本地使用、非商用的"全球热点资讯聚合系统"的最终架构设计。文档遵循"统一内容池 + 分类树 + 多视图"的核心组织思想，以合法合规为最高约束，采用 Go + Gin + GORM + SQLite 后端、Angular 前端、Wails 桌面化、NSIS 打包的技术栈，覆盖总体架构、后端与采集、合规过滤与去重、板块归口、数据模型、数据源管理、前端、安全合规、打包发布、非功能性与风险约束等全链路。
一、项目概述
(一) 项目背景与目标
本系统面向个人本地单机使用、完全非商用。其目标是通过温和、合规的方式，从全球公开资讯源采集纯事实性、时事性信息，按财经、军事、科技、政治、经济等领域分类聚合，并结合个人浏览行为形成本地画像，向用户推送个性化热点内容。系统不对外提供网络服务，所有数据仅落地本机。
(二) 设计范围
架构覆盖：数据采集与调度、合规与内容过滤、去重与归一化、存储与数据生命周期、推荐与画像、板块分类与多视图展示、数据源管理、桌面应用打包与安装包发布等全链路。系统为单机桌面形态，无云端多用户后端。
(三) 核心约束（最高优先级）
系统设计的首要属性是合法合规：仅抓取纯事实性、时事新闻的时间、地点、人物、事件、事实摘要、标题与导语；深度报道、评论、特写、新闻图片、原创稿件一律不抓取，改由外部链接经 WebView 跳转展示。严格遵守各平台 robots.txt；绝不绕过验证码、登录、反爬、防火墙、付费墙等技术保护措施；绝不高频并发或破坏目标站点；绝不采集个人隐私信息；绝不存储或处理违法违规有害内容；绝不翻墙访问境外站点，仅使用国内合规国际互联网通道。
二、设计原则与合规硬约束
(一) 总体设计原则
1. 合规优先：将 robots 校验、频控限速、内容过滤、隐私保护做成可强制生效的横切能力，而非可选附加项，并硬编码为系统约束以避免被绕过。
2. 轻量单机：以 SQLite 单文件库与单进程后端实现零部署、低资源占用；本地 API 仅绑定 127.0.0.1，程序本身不作为对外 Web 服务器。
3. 统一内容池、多视图：底层资讯只建一份表，财经/军事/科技/政治/经济前端板块只是同一内容池的筛选视图，避免重复建表、重复采集与重复存储。
4. 松耦合可扩展：数据源、过滤规则、推荐策略均以适配器/插件形式接入，新增板块或数据源只需实现接口并注册。
5. 数据最小化：只存标题、摘要、导语及事实元数据，不存全文与原图，配合自动过期清理降低风险与体积。

四、总体架构设计
(一) 分层架构
系统自上而下划分为五层，并由两条横切能力贯穿：
1. 表现层（Angular SPA）：多板块渲染、用户交互、数据源管理、WebView 外部链接展示。
2. 应用层（Wails 绑定 / 服务编排）：将前端调用编排为对领域服务的调用，统一请求分发、配置、日志与错误处理。
3. 领域服务层：采集调度、清洗过滤、去重归一、存储与生命周期、推荐画像、关注与板块聚合、热榜等服务。
4. 数据采集层：数据源适配器（IDataSource）、robots 解析器、频控限速器、并发调度器（WorkerPool / Retry）。
5. 存储层：GORM + SQLite，含资讯条目、数据源、分类、标签、用户画像、关注、浏览行为、热榜快照、过滤与采集日志、配置等表。
横切能力一（合规与内容过滤）：robots 校验、频控、违法有害内容拦截、隐私字段过滤、违规不落地，作为入库前置强制节点。
横切能力二（可观测与运维）：数据源可用性自检、任务日志、异常告警与错误提示回写。
(二) 部署架构
以 Wails 打包为单个桌面进程：进程内 Angular 资源经内置 WebView2 渲染，Go 服务在同一进程以绑定方法对前端暴露能力（Gin 仅用于内部业务逻辑，不监听局域网/0.0.0.0）。SQLite 数据文件、日志、配置存放于用户本地目录（如 %APPDATA%/HotNews/hotnews.db），与程序本体分离，升级安装不覆盖用户数据。全程无对外网络监听端口，无云端依赖，数据不外传。NSIS 安装包负责分发运行时、创建快捷方式与卸载清理。
(三) 端到端数据流
采集调度器按数据源配置的低频周期触发（未激活源不调度）→ 频控限速器与 robots 解析器做准入判定 → 数据源适配器抓取公开事实性字段（时间/地点/人物/事件/标题/摘要/导语/外链）→ 合规过滤中间层剥离隐私字段并拦截违法有害内容（命中即丢弃、仅记日志不落地）→ 去重归一后仅将标题+摘要+元信息写入 SQLite → 推荐画像服务基于浏览行为更新本地画像并对条目打分 → 前端各板块按分类与画像拉取展示。深度/原创内容仅保留外部链接，由 WebView 跳转源站展示。
五、后端架构设计
(一) 后端分层与模块划分
后端遵循 Controller/Binding 层—Service 服务层—Repository 数据访问层—Model 实体层的经典四层结构：绑定层只做参数校验与调用编排；Service 层承载采集调度、过滤、去重、推荐、关注、板块聚合等业务逻辑；Repository 层封装 GORM 对 SQLite 的读写；Model 层定义实体与表映射。各层通过接口解耦，便于单元测试与替换。
(二) 数据采集子系统（温和爬虫）
1. 数据源抽象接口：以统一接口封装不同来源（RSS/Atom、公开 API、合规公开列表页）的抓取差异，新增数据源只需实现接口并注册。核心接口约定：type IDataSource interface { TestConnect() (TestResult, error); Fetch() ([]RawNewsItem, error); GetRobotsPolicy() (allow bool, err error) }。RawNewsItem 仅含标题、摘要、导语、时间、地点、人物、事件、外链，不含正文与图片字段。
2. robots.txt 解析器：抓取前对目标 URL 做规则判定，禁止路径直接拒绝，作为采集强制准入门禁；robots 获取失败标记异常，不执行抓取。
3. 温和爬虫与频控限速器：令牌桶/漏桶限速、随机化间隔、极低并发（1-3 协程）、请求退避；UA 使用普通浏览器标识，禁止伪造头、自动提交验证码、模拟登录、绕过付费墙；遇 403/429/5xx 标记源异常并暂停后续调度。
4. 采集调度器：定时任务 + 队列方式，按数据源激活状态与自定义周期调度，支持失败重试与退避、可用性回写。采集结果不直接写库，全部送入合规过滤中间层。
(三) 合规与内容过滤中间层（入库前置拦截）
处理链路：RawNewsItem → 过滤校验 → 通过则打标写库 / 不通过则丢弃并写日志。过滤在数据落库前强制执行：违法有害内容（分裂、煽动、暴力、重大虚假谣言等）通过关键词、正则、AC 自动机敏感词库识别，命中即丢弃，不写入本地硬盘；隐私字段（PII）自动剥离或拒绝采集；仅保留事实性摘要，原创/深度/评论/图片内容不落地改存外链。支持"全局规则 + 数据源私有规则"，日志只记录来源 URL、规则 ID、原因码、时间与内容哈希，不保存违规文本本体。
(四) 去重与归一化
对采集条目做 URL 规范化与标题 SimHash/内容指纹去重，同一事件多源聚合只保留一条主记录，多源外链作为关联；板块归属按主属性归入唯一分类，避免重复采集与重复展示（详见第六章）。
(五) 存储与数据生命周期
采用 GORM + SQLite，遵循数据最小化：仅保存标题、导语/摘要、分类标签、来源、时间戳、地点/人物/事件事实字段与外部链接，不存全文与原图。articles 默认 TTL 可配置（如 7/30 天），后台定时任务清理过期资讯、热榜快照与行为关联，可选执行 SQLite VACUUM 回收空间。
(六) 推荐与用户画像引擎
通过前端埋点采集点击、停留时长、滚动、关注/取关、搜索、是否打开 WebView 原文等行为，在本地构建个人兴趣画像（分类权重 + 关键词权重 + 来源偏好），并施加时间衰减。推荐排序 = 标签匹配度 + 热度 + 时效 + 来源权重 − 已读惩罚；冷启动使用热榜与默认分类兜底。画像与打分全部本地计算，不上传任何行为数据，支持一键重置清空画像。
(七) 热榜聚合
多源热榜在本机聚合，不调用外部热榜 API。排名归一化：score = (N − rank + 1) / N × 源权重 × 时间衰减，并按标题指纹/URL 去重合并后综合展示。
(八) 接口设计
对外接口以 Wails 绑定方法为主（可选本地 Gin 仅监听 127.0.0.1 并加随机 token 防止其他程序访问），按领域分组暴露：数据源管理（CRUD、激活/取消激活、连通性测试、可用性检测、过滤规则设置）、资讯查询（按板块/分类/关键词/分页）、关注管理、热榜聚合、推荐列表、浏览行为上报、画像重置、系统配置。方法入参出参以类型化结构体定义，保证前后端契约一致。

六、板块分类与去重归口设计
(一) 核心思想：统一内容池 + 分类树 + 多视图
需求 4/5/6/7/8（财经、军事、科技、政治、经济）板块存在大量重复内容（如宏观经济、货币财政在"财经"与"经济"中均出现，评论/智库在各板块中均出现）。本架构采用"统一内容池 + 统一分类树 + 多视图"解决重复规划问题：底层 articles 表只建一份、只采集一次，财经/军事/科技/政治/经济前端板块只是同一内容池的不同筛选视图，绝不按板块重复建表或重复采集。
(二) 去重合并策略（按领域唯一归口）
1. 经济/财经重复合并：宏观经济、货币与财政、国际经济、经济研究统一归入"经济"；证券市场、固收与外汇、大宗商品、银行保险资管、国际贸易归入"财经"。财经板块引用经济宏观数据，不重复存储。
2. 分析评论统一：财经评论、政治评论、军事智库、经济研究等统一归入"分析评论"，按领域打二级标签。
3. 跨界唯一归口规则：同一事件按主属性归入唯一板块。例如军工底层芯片/新材料技术归"科技"，军工企业股价/财报归"财经"；企业发布新技术/新产品归"科技"，企业财报/股价归"财经"。

七、前端架构设计（Angular）
(一) 应用结构
采用 Angular 模块化架构：App 根模块 + 路由 + 懒加载功能模块（推荐、我的关注、热榜、财经、军事、科技、政治、经济、数据源管理、过滤规则、系统设置）。通过 Service + RxJS 封装对 Wails 绑定方法的调用与状态管理，使用共享组件统一列表卡片、详情、WebView 容器与错误提示。
(二) 页面规划
1. 推荐页：个性化推荐资讯列表，每条展示标题/摘要/来源，点击唤起 WebView 打开外部原文。
2. 我的关注页：Tab 分列"关注资讯""关注数据源"，支持取消关注，快速浏览关注对象更新。
3. 热榜页：本机聚合综合热榜，按热榜权重 + 时间衰减排序展示。
4. 分类栏目页：财经/军事/科技/政治/经济，子分类对齐需求各子项，同一内容池多视图筛选。
5. 数据源管理页：列表展示名称、类型、激活状态、运行状态、最近错误与检测时间；支持新增/编辑/删除、【测试】连通校验（返回样例摘要）、配置采集周期与请求间隔、绑定过滤规则。
6. 过滤规则管理页：新增/编辑规则，维护黑名单，区分全局规则与数据源私有规则。
7. 系统设置页：爬虫全局参数、资讯保留天数、重置用户画像、查看系统日志。
(三) WebView 组件
核心组件为受控的 Wails WebView，仅负责加载外部原始网页跳转源站阅读，前端程序本身不下载、保存外部页面的正文与图片，从源头规避版权与合规风险。
八、数据模型设计
(一) 核心实体与关键关系
数据源(Source) 一对多 资讯条目(NewsItem)；NewsItem 多对一 分类(Category)、多对多 标签(Tag)、多对多 关注(Follow 内容维度)；用户画像(UserProfile) 聚合 浏览行为(ViewLog) 并驱动推荐排序；过期时间戳驱动自动清理。所有表均本地 SQLite 存储，单用户无需账号体系。
(二) 关键表结构
资讯主表 news_info（核心，无正文/图片字段）：

九、数据源管理架构
数据源全生命周期由"配置—调度—采集—自检—过滤"闭环管理：支持用户自定义新增、激活/取消激活；【测试】功能即时验证能否从该数据源取数（请求 robots、拉取样例、解析字段并返回可用性）；可配置过滤规则、采集频率、超时、UA 与分类映射；后台周期性做可用性自动检测，标注可用/不可用并回写报错提示（网络错误、robots 禁止、限流、解析失败等），供前端展示。所有采集均受 robots 与频控约束，禁止配置需登录/验证码/付费墙/翻墙绕过的源。
十、安全与合规架构
合规控制贯穿采集到展示全链路：robots 强制准入、温和限速与低并发、严禁突破任何技术保护措施、不采集个人隐私、落库前过滤违法有害内容且不留存、仅存标题+摘要+导语不存全文原图、TTL 自动过期清理、禁用境外违规通道仅用国内合规国际互联网通道、本地 API 仅绑定 127.0.0.1、应用内无任何对外分享/上传/发布/他人访问入口、严格非商用。上述项以横切组件与配置开关形式硬编码为系统约束。程序不内置翻墙/代理，网络完全依赖本机系统网络；过滤为简易关键词+敏感词库能力，无法识别全部变体有害内容，软件文档声明本工具仅限个人学习研究，数据源需自行确认授权与当地法律合规。
十一、打包与发布架构
(一) Wails 编译与 NSIS 打包
开发调试使用 wails dev（Go 后端 + Angular 前端联合调试）；wails build 将 Go 后端与 Angular 静态资源编译为单一 Windows 桌面 exe（完成绑定生成、前端内嵌与运行时打包）；NSIS 脚本将产物封装为安装/卸载程序，处理安装目录、依赖与配置初始化、开始菜单与桌面快捷方式、可选开机启动、卸载清理逻辑。SQLite 数据库、日志、配置写入用户目录，不写安装目录，升级安装不清除用户数据。
(二) 推荐工程目录结构
cmd/app；internal/{config, server, router, models, repository, service, collector, parser, filter, robots, scheduler, recommend, hot, wails}；frontend/angular；build/nsis。
十二、非功能性设计
性能：单进程低资源占用，采集与渲染解耦，SQLite 本地读写满足个人级吞吐。可靠性：任务失败退避重试、数据源自检与错误提示、过滤命中不污染库。可维护性：分层与适配器/插件化，板块与数据源可扩展。可观测性：采集日志、可用性标识与报错回写。安全合规：作为首要非功能属性，见第十章。
十三、风险与落地约束清单
1. 网络约束：程序不内置翻墙/代理，网络完全依赖本机系统网络，说明文档提示用户不得翻墙获取资讯源。
2. 爬虫约束：代码强制 robots 校验，禁止绕过登录/验证码/付费墙，并发与延时参数默认保守。
3. 版权约束：只存储标题+摘要+导语，正文与图片全部跳转外部 WebView，本地不存原文。
4. 网络服务约束：Gin 不监听公网/局域网地址，Wails 仅进程内绑定，外部无法访问程序。
5. 过滤能力说明：简易关键词过滤无法识别全部变体有害内容，工具仅限个人学习研究。
6. 使用边界：功能全部限定本地，禁止任何形式对外分享、导出分发抓取资讯内容，禁止商用。
十四、可选扩展与演进建议
在保持合规硬约束的前提下，可演进：数据源配置 JSON 导入导出、资讯元数据 CSV 导出（仅标题/摘要/外链，不含原文）、基于 SQLite FTS 的标题+摘要本地全文检索、子分类与多条件组合筛选；进一步细化推荐算法、增强板块去重与归一能力，并完善安装包的静默升级机制。
总结：本架构以"合规采集—过滤落地—去重归一—最小化存储—本地画像推荐—统一内容池多板块展示—桌面打包发布"为主线，采用 Go/Gin/GORM/SQLite + Angular + Wails + NSIS 技术栈，通过统一内容池与分类树解决 4/5/6/7/8 板块重复建设问题，形成轻量、单机、可控、可扩展的个人热点资讯聚合系统。
