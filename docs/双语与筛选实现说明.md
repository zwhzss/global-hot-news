# 双语与筛选功能实现说明

对应本轮四项需求。需求 3（双语内容如何生成）的方案单独写在
[双语内容生成方案.md](双语内容生成方案.md)，本文说明其余三项的实现、顺带发现的三个隐藏
bug，以及验证方式。

---

## 一、所有板块支持汉语和英语（需求 1）

界面文案不再硬编码，统一走 `I18nService`：

- 新增 `frontend/angular-app/src/app/services/i18n.service.ts`，内置中英词典（导航、表头、
  筛选栏、空状态、按钮、日期相对时间、设置项、翻译设置），`t(key, params)` 取词，
  未知 key 直接回显 key 本身（拼错能立刻看见）。
- 侧边栏顶部新增 **中文 / English** 切换按钮；切换即时生效，覆盖导航、页面标题、分类名、
  分类描述、筛选栏、空状态、分页、关注按钮、时间显示。
- 语言选择同时写入 `localStorage` 和数据库 `system_settings.ui_language`，启动时以数据库为准。
  只存 localStorage 太脆弱：WebView2 配置目录一旦被清掉，用户选过的英文就会悄悄变回中文。
- **分类名与描述真正双语化**：`categories` 表新增 `name_en` / `description_en`，40 个内置分类
  全部补齐。旧版本把英文描述写在了中文列里（中文界面显示英文说明），种子逻辑现在会在
  “该描述仍等于内置英文默认值”时替换为中文——用户手工改过的描述不会被覆盖。

覆盖板块：推荐、我的关注、热榜、财经、军事、科技、政治、经济（+ 数据源、设置）。

## 二、文章内容双语 tab 切换（需求 2）

文章表新增双语字段：

| 字段 | 说明 |
|---|---|
| `title` / `summary` / `lead` | **原文**，采集时写入，任何情况下都不被译文覆盖 |
| `lang` | 原文语言（`zh` / `en`），由 `internal/langdetect` 纯规则判定 |
| `title_zh` / `title_en` / `summary_zh` / `summary_en` / `lead_zh` / `lead_en` | 双语内容 |

- 入库时就把原文那一侧填好（`translator.EnsureOriginal`），所以任何文章至少有一种语言可读，
  不依赖翻译服务是否可用。
- 每张卡片右上角有 **中文 / English** 两个 tab，切换显示该语言的标题、导语、摘要；默认跟随
  界面语言，但单张卡片的切换不会影响其他卡片。
- 徽章明确标注当前显示的是 **原文** 还是 **译文**，不会把译文伪装成原文。
- 该语言译文还没生成时，卡片显示原文并提示“该语言的译文尚未生成”，并提供 **立即翻译**
  （单篇按需翻译）；翻译服务未启用时提示直接指向“设置 → 双语翻译”。
- 原文语言无法判定时（例如纯数字标题）按原文展示，不提示翻译，因为确实无从翻起。

> 截图中的 `[EN] ...` / `[中译] ...` 是**验证用桩程序**的输出（见第五节），不是应用行为。

## 三、缺省显示当天文章 + 追加筛选条件（需求 4）

文章表只会越来越大，所以每个板块的默认视图改为 **今天 + 时间倒序**。

- 新增统一的筛选项结构 `models.NewsQuery`，前端 `NewsQuery` 与之逐字段对应：
  分页、分类 slug、分类前缀、来源、仅关注、**标题模糊关键字**、**日期区间/预设**、排序方式。
- Wails 绑定新增 `NewsSearch` / `HotRankSearch` / `RecommendSearch` / `FollowedSearch`，
  四个板块共用同一套筛选语义，筛选栏行为完全一致。
- 筛选栏（`news-filter` 组件，各板块共用）：
  - 日期快捷：今天（默认）/ 近 7 天 / 近 30 天 / 全部日期 / 自定义区间；
  - **有数据的日期**下拉：只列出数据库里真正存在文章的日期，避免选了空日期；
  - **标题模糊查询**：同时匹配 `title` / `title_zh` / `title_en`，中文英文都能搜到，
    `%`、`_` 已转义，不会变成“匹配全部”；
  - 排序：按时间倒序 / 按热度；右侧显示命中条数。
- 时间比较用 SQLite 的 `datetime()` 归一化后再取本地日期：
  `publish_time` 在不同源之间混用 `+00:00` 与 `+08:00`（还带微秒），按字符串比较会排错；
  Go 零值时间（无发布时间的条目）回退到 `fetched_at`。
- 未填写日期时不会被当成“当天”，只有前端默认值会请求 `today`，其他调用方传什么就是什么。

## 四、顺带发现并修复的五个隐藏 bug

这五个都不是本次需求引入的，但都会直接破坏本次需求的效果。

### 4.1 采集器信号量死锁：18 个源里只有 3 个真的被抓过

`collector.runCollectionCycle` 把 `defer func(){ <-s.semaphore }()` 写在了 **循环体内**，
defer 属于外层函数，于是所有许可要等到整个采集周期结束才释放。`max_concurrency=3` 时，
第 4 个启用源会永久阻塞：后面的源再也抓不到，调度 goroutine 也再不会 tick。

数据库里的证据：`fetch_logs` 只有 49/50/51 三个源（`created_at DESC` 排序后正好是最新三个），
14 个中文源从来没有产生过任何一条抓取记录——**这就是“中文内容一直没有”的根本原因**，
也直接导致双语功能里中文侧永远为空。

修复：把许可的获取与释放收进 `collectSource()`，每个源独立释放。
新增 `collector_test.go::TestRunCycleVisitsEveryActiveSource`（6 个启用源 + 2 个并发许可，
旧代码在该用例下必然超时）防回归。

修复后一次采集周期：**18 个启用源全部被抓取**（13 号 Solidot 被 robots.txt 正确拒绝），
新增 1400+ 篇文章，其中中文 900+ 篇。

### 4.2 用 HTML 解析器解析 RSS：摘要全丢、发布时间几乎全部失效

`parseRSS` 用 `golang.org/x/net/html`（HTML 解析器）解析 RSS/Atom。实测把一份正常 RSS 丢给
它，得到的 `<item>` **一个子节点都没有**——HTML 对 `title`/`link` 的处理规则与 XML 不同。
于是每个源都悄悄落到字符串兜底解析器，而兜底解析器：

- 只按 `<item>` 字符串切分，**完全不支持 Atom 的 `<entry>`**；
- 不读 `<description>` → 数据库里 **1494 篇文章 100% 摘要为空**（而《需求.md》第 1、7 条
  明确要求保存摘要）；
- 用大小写敏感的 `<pubDate>` 匹配，遇到 `<dc:date>` 或小写 `<pubdate>` 就放弃 →
  **93%（1386/1494）的发布时间退化成“抓取时刻”**，直接使“缺省显示当天文章”变成“今天抓到的文章”。

修复：用 `encoding/xml` 做结构切分（RSS `<channel><item>` 与 Atom `<feed><entry>` 同时支持），
字段用大小写不敏感、允许命名空间前缀的正则提取，链接同时支持 `<link>url</link>` 与
`<link href="..."/>`；发布时间支持 12 种真实存在的格式；保留字符串兜底以应对畸形文档。
`rss_test.go` 覆盖 RSS/CDATA 摘要、Atom、`content:encoded` 回退、兜底路径、时间格式、
摘要长度上限。

修复后重新采集的结果：

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 有摘要的文章 | 0 / 1494 | **1428 / 1484（96%）** |
| 发布时间退化为“抓取时刻” | 1386 / 1494（93%） | **116 / 1484（8%）** |

（人民网“要闻快讯”这个源本身就只有标题、没有摘要，且发布日期停留在 2016 年——已正确解析，
这类条目不再是“今天”的文章，属于预期行为。）

### 4.3 分类器读不懂中文，且用子串匹配英文

分类器从分类的 **slug + 名称 + 描述** 里按空格切词生成关键词，有两个问题：

- 中文描述没有空格，切出来是**一整个长词**（如“国内生产总值、CPI、PPI……），永远匹配不上；
  把描述改成中文之后，新文章的分类命中率直接变成 0；
- 英文关键词用 `strings.Contains` 做子串匹配，`AI` 会命中 `said`、`chair`、`campaign`，
  再加上标题里的 URL 含 `military` / `tech` 等模块词，结果 `military-equipment` 一个分类
  就吞掉了 616 篇（几乎整个军事源）。

修复：
- 关键词改为**独立的、人工维护的术语表**（`classifier/keywords.go`，40 个分类 × 4~14 个中英术语），
  不再从面向用户展示的描述文本里猜词；
- 中文按子串匹配（中文没有词边界），**英文按整词匹配**（`AI` 不再命中 `said`）；
- 匹配文本不再包含 URL（URL 描述的是“源”，不是“这条新闻”）；
- 新增 `ClassifyUncategorized`（启动时自愈历史未分类文章）与 `ReclassifyAll`
  （改完分类后可全量重建关联），绑定为 `NewsReclassify(rebuild, limit)`。

修复后：分类命中率 45%（681/1484），且各模块分布合理
（财经 374 / 经济 254 / 科技 213 / 军事 113 / 政治 84），不再有单分类吞掉整个源的假阳性。
未命中的文章不再显示“未知”，而是**回退显示数据源名称**（如“中国新闻网-政治”），
这类文章仍完整出现在「推荐」和「热榜」中。

### 4.4 GB2312/GBK 源未转码，标题存成乱码

`中国新闻网-政治` 返回的是 GB2312 编码的 XML，解析器直接把原始字节当 UTF-8 存库，产生 10 条
非法 UTF-8 标题：中文界面显示乱码，语言判定因为没有汉字而判成英文，翻译方向也跟着反了。

修复：新增 `internal/service/parser/charset.go`，三个适配器（RSS/HTML/JSON）统一走
`decodeBody`：优先 HTTP `Content-Type` 的 charset → 文档内 XML 声明 / `<meta charset>` →
两者都没有且不是合法 UTF-8 时按 GB18030 解码（GB18030 是 GBK/GB2312 的超集）。
支持 GB2312/GBK/GB18030/Big5。测试 `charset_test.go` 覆盖 XML 声明、响应头、无声明回退、
UTF-8 不受影响、空响应五种情况。

### 4.5 推荐服务里的伪键与重复映射

- `recommend/service.go` 用 `string(rune(b.SourceID))` 当权重键，得到的是控制字符，
  只是“碰巧”能区分来源。已改为 `strconv`，并把分类权重改为按文章真实分类聚合
  （原先分类权重恒为 0，只有来源权重在起作用）。
- `recommend.service.ts` / `hotrank.service.ts` / `follow.service.ts` 各自维护了一份
  `toArticle` 映射副本，每份都漏字段。已合并为 `news.service.ts` 里唯一的 `toArticle`。
- `ResetProfile` 执行的是 `DELETE FROM user_profile`，而 GORM 的实际表名是 `user_profiles`，
  这条语句一直是空操作。已修正。
